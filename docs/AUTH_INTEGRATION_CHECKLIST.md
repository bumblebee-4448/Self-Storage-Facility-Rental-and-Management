## Backend follow-up

For the local development origin, configure the backend/proxy to:

- Return a successful preflight response (normally 204) for `OPTIONS /auth/refresh`.
- Allow the exact origin `http://localhost:5173`; do not use `*` with credentialed requests.
- Return `Access-Control-Allow-Credentials: true`.
- Allow `POST` and the request headers used by the frontend, including `content-type` and `accept` where required.
- Include matching allow-origin and allow-credentials headers on actual auth responses, including 401 and 500 error responses. If origins are selected dynamically, include `Vary: Origin`.
- Configure cookie `HttpOnly`, `Secure`, `SameSite`, domain, and path for the intended deployment topology. For cross-site frontend/backend origins, confirm the backend's intended `SameSite=None; Secure` policy with the backend team.

Repeat the checks for the actual deployed frontend origin before relying on browser session persistence. This task did not change the backend or weaken browser security settings.
